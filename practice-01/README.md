## 5. Задание 2. Исследование типов и преобразований

**Файл:** `practice-01/js/types.js`.

| № | Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---:|---|---|---|---|---|
| 1 | `"8" + 2` | строка `"82"` | `"82"` | `string` | Оператор `+` со строкой выполняет конкатенацию: число `2` превращается в `"2"` и присоединяется к `"8"`. |
| 2 | `"8" - 2` | число `6` | `6` | `number` | Оператор `-` определён только для чисел, поэтому строка `"8"` преобразуется в число `8`. |
| 3 | `Number("8") + 2` | число `10` | `10` | `number` | Явное преобразование строки в число, затем арифметическое сложение. |
| 4 | `"12" > "3"` | `false` | `false` | `boolean` | Строки сравниваются посимвольно, как в словаре: `"1"` < `"3"`, значит `"12"` < `"3"`. |
| 5 | `12 === "12"` | `false` | `false` | `boolean` | Строгое равенство не преобразует типы: число и строка никогда не равны. |
| 6 | `Number("")` | `0` | `0` | `number` | Пустая строка по правилам `Number()` преобразуется в `0`. |
| 7 | `Number("text")` | `NaN` | `NaN` | `number` | Строка, не являющаяся числом, даёт `NaN`, тип которого — `number`. |
| 8 | `Boolean("false")` | `true` | `true` | `boolean` | Логическое преобразование непустой строки всегда даёт `true`, даже если её содержимое — слово «false». |
| 9 | `typeof null` | строка `"object"` | `"object"` | `string` | Историческая особенность JavaScript: `typeof null === "object"`, хотя `null` — примитив. Тип самого результата выражения — строка. |
| 10 | `typeof NaN` | строка `"number"` | `"number"` | `string` | `NaN` относится к типу `number`, поэтому `typeof NaN === "number"`. Тип результата выражения — строка. |

**Вывод по заданию 2:**

- Оператор `+` со строкой всегда склеивает, а не складывает — нужны явные преобразования (`Number()`).
- Пустая строка и строка из пробелов дают `0`, поэтому `Number("")` — не признак корректного ввода.
- `Boolean("false")` возвращает `true`, потому что проверяется только непустота строки.
- `typeof` не различает `null` и объекты; для проверки числа одного `typeof` мало — нужны `Number.isFinite()` и `Number.isInteger()`.

### 6.3. Пояснения к решению

- Порядок проверок: сначала тип (`typeof !== "number"`), затем `NaN`, затем целочисленность, затем границы, затем `completedTasks > totalTasks`, и только потом — расчёт.
- Случай `0, 0` обрабатывается отдельной ветвью до деления: иначе `completedTasks / totalTasks` дало бы `NaN`.
- Статус выбирается по исходным количествам, а не по округлённому проценту, чтобы поведение не зависело от `toFixed(1)`.
- Процент выводится как `percentage.toFixed(1)` — метод возвращает строку, подходящую для вывода (например, `70.0`).

### 7.4. Пояснения к решению

- Сначала полностью проверяются `totalTasks` и `completedTasks` по правилам задания 3.
- Затем проверяется `dailyLimit`: **сначала тип** (`typeof !== "number"`), потом `NaN`, потом целочисленность, потом диапазон `1…1000`. Если поставить проверку диапазона раньше типа, то `"2" > 1000` даст `false`, и будет неверное сообщение.
- Проверка `dailyLimit` выполняется **до** ветки `0, 0`, потому что по заданию норма должна проверяться даже при отсутствии оставшихся задач.
- Если `remainingTasks === 0`, цикл не запускается и выводится `Потребуется дней: 0`.
- На каждой итерации `tasksToday = Math.min(remainingTasks, dailyLimit)` — за последний день нельзя выполнить больше, чем осталось.
- Условие цикла `while (remainingTasks > 0)` гарантирует завершение: `remainingTasks` уменьшается минимум на 1 за итерацию, так как `dailyLimit ≥ 1`.

for (let taskNumber = 1; taskNumber <= 4; taskNumber += 1) {
  controlSum += taskNumber;

### 9.2. Почему недостаточно просто вызвать `Number()`

`Number()` умеет молча превращать в числа значения, которые не являются корректным вводом:

- `Number("")` → `0`;
- `Number("   ")` → `0`;
- `Number("Infinity")` → `Infinity`, и `Number.isFinite(Infinity)` = `false`;
- `Number(null)` → `0`;
- `Number(undefined)` → `NaN`, но `NaN` не отличить от результата для строки `"abc"` без дополнительных проверок.

Если не отклонять пустые строки и `null` до вызова `Number()`, пользователь, забывший ввести число, получит не ошибку, а «валидное» значение `0`. Поэтому порядок такой: проверить, что вход — именно строка, удалить пробелы, отклонить пустую строку, потом `Number()`, потом `Number.isFinite()`, `Number.isInteger()` и диапазон.
