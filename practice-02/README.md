## 3. Функции, ссылки и копирование

Прогноз заполнялся до первого запуска файла `examples/functions-and-references.js`.

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | `sum(2, 3) → 5`, `sum("2", 3) → "23"` | `5` и `"23"` (строка) | Оператор `+` конкатенирует строки. Функция не преобразует типы автоматически в соответствии с назначением. |
| 2 | До исправления: `undefined` | До исправления: `undefined`. После исправления: `16` (число) | Стрелочная функция с фигурными скобками не имеет краткого возврата. Без `return` результатом вызова будет `undefined`. |
| 3 | `product.stock → 5`, `product === alias → true` | `5` и `true` | Присваивание объекта копирует ссылку, а не значение. Оба имени указывают на один объект. |
| 4 | `products[0].stock → 7`, `products === copy → false`, `products[0] === copy[0] → true` | `7`, `false`, `true` | Spread массива копирует только верхний уровень. Элементы (объекты) остаются общими ссылками. |
| 5 | `product.stock, first.stock, second.stock → 3, 8, 3`, `product === first → false` | `3, 8, 3`; `false` | Порядок свойств в литерале важен: `{ ...product, stock: 8 }` → `stock: 8`; `{ stock: 8, ...product }` → `stock` перезаписывается значением из `product` (3). |
| 6 | `makeCaption()` → `"Без названия"`; `makeCaption(undefined)` → `"Без названия"`; `makeCaption(null)` → `null`; `makeCaption("")` → `""` | Совпало с прогнозом | Значение по умолчанию применяется только при отсутствии аргумента или при `undefined`. `null`, `0` и пустая строка — это переданные значения. |

**Исправление эксперимента 2.** Изначально тело стрелочной функции было в фигурных скобках без `return`:

```js
const square = (value) => {
  // пропущен return
  value * value;
};
```

В краткой форме (`(value) => value * value`) результат выражения возвращается автоматически, но при теле в фигурных скобках этого не происходит. До исправления `square(4)` возвращал `undefined`; после добавления `return value * value;` вызов `square(4)` возвращает число `16`. В отчёте сохранены оба результата.

**Различие копирования массива и его элементов.** В эксперименте 4 `const copy = [...products]` создаёт новый массив, но объекты внутри — те же самые (одинаковые ссылки). Поэтому изменение `copy[0].stock` отражается на `products[0].stock`. Чтобы получить независимые записи, необходимо копировать каждый объект: `const copy = products.map((p) => ({ ...p }))`.

## 4. Модель данных и функции

Модель задачи во всех обязательных заданиях одна:

```js
{
  id: 20,
  title: "Подготовить демонстрацию",
  completed: false,
  priority: "medium"
}
```

| Поле | Правило |
|---|---|
| `id` | Число; `Number.isSafeInteger(id)` и `id > 0`. В пределах одного списка идентификаторы уникальны. |
| `title` | Строка; после `trim()` длина 1–100. В объект записывается очищенная строка. Внутренние пробелы сохраняются. |
| `completed` | Логическое значение. При создании всегда `false`. |
| `priority` | Одно из `"low"`, `"medium"`, `"high"`. По умолчанию — `"medium"`. |

### Назначение файлов

| Файл | Ответственность |
|---|---|
| `src/data.js` | Экспорт общего набора `demoTasks`, номера варианта и набора `variantTasks`. Только данные, без логики и вывода. |
| `src/task-service.js` | Девять прикладных функций. Только проверки и операции над переданным массивом. Без `console.log`, без чтения `demoTasks`. |
| `src/main.js` | Общий и индивидуальный сценарии, вывод результатов, обработка отказов. Логика не дублируется. |
| `examples/functions-and-references.js` | Шесть независимых учебных экспериментов. |
| `checks.js` | 35 общих проверок + три собственные. Использует `node:assert/strict`. |

### Форматы результатов

- Создание (`createTask`): при успехе — `{ ok: true, task }`, при ошибке — `{ ok: false, error }`.
- Операции (`addTask`, `setTaskCompleted`, `renameTask`, `removeTask`): при успехе — `{ ok: true, tasks }` (новый массив), при ошибке — `{ ok: false, error }`.
- Чтения (`findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`): возвращают соответствующее значение без объекта-обёртки. Отсутствие записи при поиске — `undefined`.

### Ответы на контрольные вопросы

**Почему `id` не равен индексу.** Индекс показывает текущее место записи в массиве и меняется после удаления соседних элементов. `id` идентифицирует задачу и не меняется на протяжении её жизни. Поиск по `id` через `tasks[id]` вернул бы случайный элемент, а не целевую задачу.

**Почему `getTaskStats` возвращает число, а не строку.** Округление — операция отображения. Функция расчёта должна возвращать «сырое» числовое значение, чтобы вызывающий код сам решал, сколько знаков показывать, и мог сравнивать числа без разбора строк. В `main.js` для вывода используется `progress.toFixed(1)`. Для пустого списка соглашением зафиксирован `progress = 0`.

**Какие объекты копируются при изменении задачи.** При успешной операции возвращается новый массив (созданный через spread массива, `map` или `filter`). Изменяемая запись заменяется новым объектом, полученным через spread старого объекта с заменой целевого поля. Неизменённые записи могут переиспользоваться: их свойства не трогаются. Входной массив и его объекты никогда не модифицируются.

## 9. Вывод

По сравнению с ПР1 код перестроен вокруг данных-объектов и чистых функций: вместо отдельных переменных используется массив объектов, вместо линейного сценария — модули `data.js` / `task-service.js` / `main.js` с ясным разделением ответственности.

Возвращаемые значения стали центральным механизмом: расчётные функции (`getTaskStats`, `getPendingTasks`, `getTaskTitles`) возвращают числа, массивы и объекты, а вывод выполняет `main.js`. Это позволяет в ПР3 вызывать те же функции из обработчика события без изменения их тела.

Иммутабельность проверена на нескольких уровнях. Во-первых, в `checks.js` входной массив и все его записи обёрнуты в `Object.freeze` — ни одна из девяти функций не бросает `TypeError`. Во-вторых, в `main.js` сохраняются снимки `demoTasks` и `variantTasks`, и после всех операций сравниваются с исходным состоянием. В-третьих, в собственных проверках сравниваются ссылки на новые массивы и на изменённые записи, чтобы убедиться, что при успехе создаются именно новые объекты, а не мутируются старые.

Главная ошибка, которую пришлось исправить, — отсутствие `return` в стрелочной функции с телом в фигурных скобках (эксперимент 2). Без `return` выражение вычислялось, но результат терялся, и вызов возвращал `undefined`. Дополнительно по ходу работы выяснилось, что spread массива (`[...products]`) не делает независимых копий вложенных объектов: изменения в `copy[0].stock` видны в `products[0].stock`. Это определило требование создавать новый объект изменяемой записи через spread объекта, а не полагаться только на копию массива.
