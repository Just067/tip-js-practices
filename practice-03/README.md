## Что перенесено из ПР2

Из ПР2 скопированы два модуля: `src/task-service.js` и `src/data.js`.

* `task-service.js` реализует модель задачи и операции над массивом: `createTask`, `findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`. Все функции возвращают либо `{ ok: true, … }`, либо `{ ok: false, error: "…" }`. Обращения к `document` и вывод в консоль в модуле отсутствуют, что позволяет использовать его и в браузере, и в Node.js.
* `data.js` содержит общий контрольный набор `demoTasks` (id `[1, 4, 7, 10]`), номер варианта `variantNumber = 7` и набор `variantTasks` из шести задач с id `[11, 23, 37, 41, 58, 64]`.

При переносе потребовалось только привести импорт проверок к новой папке. Логику ПР2 в `task-service.js` менять не пришлось; повторный прогон `npm run check:service` это подтверждает (35 из 35 сценариев).

### Отладка через DevTools

В обработчике кнопки установлена точка останова на строке `title.textContent = "…"`. В момент остановки:

* `event.target` — `span#lab-label`;
* `event.currentTarget` — `button#lab-button`;
* `event.eventPhase` — `3` (всплытие, потому что обработчик стоит на родителе цели);
* после `closest("button[data-task-id]")` возвращается именно кнопка, а не вложенный `span`.

Это подтверждает, что при делегировании в приложении нужно искать кнопку через `closest`, а не читать `dataset` прямо у `event.target`.

## Организация кода

| Модуль | Ответственность | Чего в нём нет |
|---|---|---|
| `task-service.js` | Прикладные операции ПР2 над массивом задач. Чистые функции, возвращающие новый массив или `{ ok: false }`. | DOM, событий, глобального состояния. |
| `task-selectors.js` | Чистая функция `getVisibleTasks(tasks, filter)`: возвращает новый массив — все задачи, только невыполненные или только выполненные. | Изменения входных задач, DOM. |
| `task-view.js` | `createTaskElement`, `renderTaskList`, `renderSummary`, `renderEmptyState`. Отвечает только за DOM. | Изменения задач, подписок на события. |
| `main.js` | Держит `currentTasks` (полный массив) и `currentFilter`, обрабатывает клики по списку и фильтрам, вызывает сервис и `renderApp()`. | Повторной реализации поиска, удаления и расчёта прогресса. |

Ключевые инварианты приложения:

* `currentTasks` хранит полный массив; выборка по фильтру вычисляется в `renderApp` и не записывается в `currentTasks` — иначе кнопка «Все» не смогла бы вернуть скрытые задачи.
* Обработчики навешаны один раз на `#task-list` и `#task-filters`. Внутри `renderApp` новые подписки не создаются, поэтому одно нажатие всегда вызывает ровно одно изменение.
* Сводка считается через `getTaskStats(currentTasks)`, то есть по полному списку, а «Показано» — по видимой выборке.

## Отладка и клавиатура

Точка останова установлена на строке `const idRaw = card.dataset.taskId;` в `handleTaskListClick` (файл `src/main.js`). В момент остановки при клике на вложенный `span.action-label` кнопки `toggle` у задачи с `id = 4`:

* `event.target` — `HTMLSpanElement` (вложенная подпись);
* `event.currentTarget` — `HTMLUListElement#task-list` (контейнер с обработчиком);
* `button` после `event.target.closest("button[data-action]")` — `HTMLButtonElement` с `data-action="toggle"`;
* `card` после `button.closest("li[data-task-id]")` — `HTMLLIElement` с `data-task-id="4"`;
* `idRaw` — строка `"4"`, `id` после `Number(…)` — число `4`, `Number.isSafeInteger(id) === true`;
* `findTaskById(currentTasks, 4)` возвращает объект `{ id: 4, title: "Подготовить модель задач", completed: false, priority: "high" }`;
* `result` от `setTaskCompleted(currentTasks, 4, true)` — `{ ok: true, tasks: [...] }`, поле `tasks` содержит новую версию задачи 4 с `completed: true`, остальные объекты те же;
* после `renderApp()` в DOM появилась карточка с `is-completed`, а `#task-summary` показывает `4 / 3 / 1 / 75.0% / 4`.

**Клавиатура.** Tab последовательно переводит фокус по кнопкам фильтров, затем по кнопкам карточек. Enter и Space активируют кнопку. После переключения статуса фокус остаётся на кнопке `toggle` той же задачи; после удаления карточка исчезает, и фокус переходит на активную кнопку фильтра — это делает `restoreTaskFocus(id, action)`.

**Отказ по некорректному id.** Через панель Elements атрибут `data-task-id` карточки с `id = 4` временно меняется на `777`. Клик по кнопке удаления: в `#operation-message` появляется «Задача не найдена в текущем списке.», сводка и список не меняются. Затем значение меняется на `4abc`: `Number("4abc")` даёт `NaN`, `Number.isSafeInteger(NaN) === false`, выводится «Некорректный идентификатор задачи.», данные не изменяются. Корректный выбор фильтра пересоздаёт карточки из настоящего массива и очищает сообщение.

## Вывод

В ходе работы прикладные функции ПР2 подключены к браузерному интерфейсу без изменения их контрактов. Реализованы:

* создание карточек средствами DOM (`createElement`, `textContent`, `append`, `replaceChildren`);
* делегирование клика на контейнер `ul#task-list` через `closest` и `contains`;
* чтение `data-task-id` с обязательной проверкой `Number.isSafeInteger` и `id > 0`;
* разделение состояния на полный массив `currentTasks` и режим `currentFilter`;
* обновление списка, сводки, счётчика «Показано», пустого состояния и активного фильтра после каждого изменения;
* различение «список пуст» и «нет задач по фильтру»;
* возврат клавиатурного фокуса после перерисовки.

Ключевые различия, закреплённые практикой:

* изменение данных и изменение DOM — разные операции; удаление `<li>` не является удалением задачи, а удаление элемента из `currentTasks` не является «просто DOM-операцией»;
* фильтрация не должна подменять `currentTasks` — видимая выборка всегда вычисляется заново;
* `textContent` безопасен для пользовательских названий, `innerHTML` в этой работе не используется;
* обработчики вынесены за пределы `renderApp`, поэтому одно нажатие всегда вызывает одно изменение;
* прикладная логика (`task-service.js`) не знает о DOM — это упростит её повторное использование и переход к React.

Ошибок, потребовавших изменения прикладной логики, при выполнении работы не возникло; перенос функций ПР2 и адаптация импорта проверок прошли без правок. Оба набора проверок пройдены полностью: 35 из 35 для сервиса и 36 из 36 для браузерного интерфейса.
